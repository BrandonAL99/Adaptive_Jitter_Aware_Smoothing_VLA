USAGE NOTES
-----------
# Baseline eval (use eval_libero.py for cleaner dataset, no action_raw column):
python simulation/scripts/eval_libero.py \
    --model HuggingFaceVLA/smolvla_libero \
    --task libero_object --episodes N --seed 42 \
    --output-dir libero_analysis/claude_results/baseline_Nep \
    --hf-dataset BrandonAL/claude_libero_baseline_Nep

# Low-pass eval (eval_libero_processed.py for processed datasets):
python simulation/scripts/eval_libero_processed.py \
    --model HuggingFaceVLA/smolvla_libero \
    --task libero_object --episodes N --seed 42 \
    --processor lowpass --lowpass-cutoff 3.0 --lowpass-order 2 \
    --output-dir libero_analysis/claude_results/lowpass_Nep \
    --hf-dataset BrandonAL/claude_libero_lowpass_Nep

# To run on cloud GPU (add MUJOCO_GL=osmesa for headless):
MUJOCO_GL=osmesa python simulation/scripts/eval_libero_processed.py ...

# To add a new processor:
#   1. Add class to libero_analysis/action_processors.py
#   2. Register in _REGISTRY dict at bottom of that file
#   3. Use --processor <name> in eval_libero_processed.py


KNOWN ISSUES / CAVEATS
-----------------------
- SER is unreliable for short episodes (T < 50 steps). Run longer evals on GPU.
- LowPassFilterProcessor init on first step: zi is scaled by first action, so
  there is no start-up transient on step 0 (action_raw[0] == action[0]).
- On CPU: ~5 min per 10 steps (SmolVLM2-500M). Use GPU for real evals.
- The baseline and low-pass raw Sm differ slightly (0.009076 vs 0.008835)
  because they are different eval runs -- seed makes the env deterministic but
  the policy itself has some stochasticity at the torch level. For perfectly
  repeatable comparison, use the action_raw column from the lowpass dataset.
