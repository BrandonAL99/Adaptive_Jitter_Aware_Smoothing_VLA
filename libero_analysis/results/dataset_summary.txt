─────────────────────

exec_steps=1   → policy re-queries observations every step  (original lerobot eval)

NOTE on eval_HFvla_* datasets: created with lerobot's native eval script which
stamped timestamps at render_fps=80. Action data is valid; DT for TC metrics
should be 1/30 (one action per env.step call confirmed from eval log: n_action_steps=1).

COMPARISON STRUCTURE FOR THESIS
────────────────────────────────
All 4 processor conditions use identical settings (exec-steps=50, seed=1000, 10 eps/task):

  chunk50_identity  →  chunk50_lowpass_2hz  }  baseline vs smoothed:
  chunk50_identity  →  chunk50_lowpass_4hz  }  does TC improve?
  chunk50_identity  →  chunk50_lowpass_6hz  }  does SR drop?
  chunk50_identity  →  chunk50_ajas         }  proposed method vs baselines

Metrics reported per condition:
  - Success rate (SR) per suite and overall
  - Sm_mean (weighted mean frequency, lower = smoother)
  - SER_mean (signal energy ratio below 1Hz, higher = smoother)
  - Both computed on proc_actions (after processor applied)
